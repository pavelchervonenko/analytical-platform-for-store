# ADR-0003: Независимая атрибуция гарантий для attach-rate

Финансовый факт остаётся в документе LiveSklad. Решение уточняет аналитическую часть
[ADR-0001](ADR-0001-return-employee-attribution.md), сохраняя его финансовое правило.
Новая методика применяется при включённой настройке атрибуции; состояние production из кода
не выводится.

Обычные гарантии учитываются у исходной продажи устройства: тип, дата, сотрудник. Однотипный
документ допускает групповую автоматическую связь. Для смешанного документа руководитель
выбирает строки устройств и распределяет полное количество. Отдельная гарантия без устойчивой
связи требует ручного решения; дата, клиент, продавец и название не доказывают связь.

Гарантийный возврат наследует исходную связь; неоднозначный частичный возврат распределяется
вручную. Возврат устройства уменьшает гарантийную базу исходного периода, сохраняя покрытие
одной группы устройств. В остальных attach-метриках возвраты остаются в периоде возврата и
относятся сотруднику строки отчёта LiveSklad, как явно подтвердил заказчик. Денежный employee_id
остаётся сотрудником исходной продажи.

Конфликт исключается из гарантийных числителей, показатель предварительный. Затронутые
метрики временно исключаются из employee benchmark без нулевого штрафа; неизвестный исходный
период консервативно ограничивает обе гарантийные метрики магазина до решения. Это не заморозка
общего балла: после изменения доступных показателей веса и место могут измениться.

Права: администратор и руководитель назначенного магазина, независимо от PLAN/SHIFTS/PAYROLL.
Решения имеют автора, время, причину, ревизию и fingerprint источника/целей. Повтор sync не
сбрасывает решение; существенное изменение открывает конфликт повторно. Для изменения прошлого
решения создаётся новая ревизия; физическое редактирование истории запрещено.

Превышение количества устройств не блокирует классификацию. Отдельные предупреждения показывают
избыток, активную гарантию при возврате устройства, фактическую задержку в днях и количество
строк одного SKU с обоими типами. Порог «регулярно» или «значительно позже» не придумывается.

Межмагазинная связь не поддерживается первой версией и не обходит ограничения доступа.
Для текущего нормализованного provider-контракта отдельный ID устройства гарантии не доказан:
такие продажи попадают в ручной поиск. Старые опубликованные снимки не переписываются.
