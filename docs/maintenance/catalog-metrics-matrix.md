# Этап 4.1: категории, денежные показатели и attach-rate

## Статус и границы

Рабочая матрица для этапа 4 [плана завершения каталога](catalog-classification-architecture.md).
Категории согласованы в предыдущих партиях; участие в новых показателях не считается
автоматически согласованным вместе с названием категории. Документ разделяет действующий
контракт кода, принятую цель и отложенные расширения. Решения D1–D5 согласованы; этап 4.1
завершён по фиксации текущей матрицы правил. Это не описание внедрения в production.

Статусы «предстоит/не реализовано» в исходных таблицах ниже зафиксированы при согласовании 4.1.
Локальное продвижение 4.4–4.5: per-sale проверка CASE_UNIVERSAL, GLASS_PHONE_UNRESOLVED и
PROTECTIVE_FILM реализована общей очередью аксессуаров, типизированными целями, ревизиями
и точным наследованием возврата. Неизвестный автор подтверждённого возврата участвует в quality.
Перезагрузка показателей после записи отличает ошибку чтения от ошибки сохранения.
Следующим локальным блоком подключены два справочных AirPods/Watch attach-rate и
явный legacy-остаток общей сводки; новые коды техники сохраняют утверждённые базы.
Денежная проекция и обзор показывают состав техники по сохранённым категориям.
Датированные товарные роли D4/D5 и их per-sale пересмотр подключены локально
и проходят интеграционную проверку. Полный runtime split/P0 **не завершён**; исходные таблицы ниже сохраняют статус момента согласования 4.1.
Локальная добавочная миграция подготовила 18 отсутствовавших кодов `STANDARD` в БД,
без назначения товаров и без переписывания продаж; новые коды неактивны до
проверки P0 и рабочих расчётов. Все 46 стандартных кодов прошли локальную
сверку денежных флагов. Денежная детализация реальных продаж и gate P0
этим не доказаны. Для PS5 в `GAME_CONSOLES` остаётся отдельная зарплатная проверка.
Текущий реализованный контракт — [attach-rate](../current/product/attach-rate.md),
остаток работы — [план](catalog-classification-architecture.md).

2026-09-29 владелец подтвердил **два отдельных attach-rate аксессуаров AirPods и Apple Watch**,
с сохранением общего показателя для сводки. Рейтинговые веса этим решением не утверждены.
Технические коды двух новых метрик ниже — предложение; их интерфейс предстоит проверить в 4.2.

2026-09-30 владелец подтвердил предложенный вариант упаковки: `PACKAGING` относится к
«Прочим товарам», а не к аксессуарам или услугам; не входит в Допы и attach-rate. Количество,
выручка, себестоимость и прибыль учитываются в общем денежном охвате по обычным правилам.
Зарплатное правило и эффективный результат сохраняются. Ответ «Хорошо, давай их в PACKAGING»
закрывает D2 в контексте предложенного выше раздела и исключений, а не запускает миграцию БД.

2026-09-30 владелец также подтвердил правило `CASE_UNIVERSAL` (D3): руководитель указывает
целевой телефон конкретной продажи. Подтверждение iPhone даёт количество только в N чехлов
iPhone, Samsung — только в N чехлов Samsung, другой телефон — ни в один из этих двух N.
До подтверждения официальный вклад отсутствует. Постоянная категория остаётся CASE_UNIVERSAL,
универсальная совместимость не заменяется брендом; двойного зачёта нет. Соседство с одним
брендом в чеке само по себе не заменяет подтверждение. Это целевое правило, ещё не реализация.

Следующим ответом 2026-09-30 владелец подтвердил правило `PROTECTIVE_FILM` (D4):
подтверждённое телефонное назначение даёт вклад в существующий N FILM_PHONE; назначение
для планшета или другого не-телефонного устройства — нет. Неизвестное назначение требует
проверки продажи, до подтверждения официального вклада нет. Категория остаётся PROTECTIVE_FILM;
решение конкретной продажи не устанавливает постоянную совместимость товара. Реализация
общего механизма проверки плёнок, возвратов и пересчёта ещё предстоит на этапе 4.4.

2026-09-30 после пояснения рекомендации владелец подтвердил D5: зарядка исключительно для
Apple Watch сохраняет денежную категорию CHARGER_CABLE, но её attach-роль — аксессуар Apple Watch,
а не телефонная зарядка. В общей сводке AirPods/Watch количество учитывается через Watch один раз.
Подтверждённое назначение товара применяется автоматически без проверки каждой его продажи;
неоднозначные/конфликтующие назначения требуют проверки. Одного упоминания Watch недостаточно
для вывода исключительной совместимости. Зарядные станции для нескольких устройств под это
правило не подпадают; одна станция не становится тремя проданными аксессуарами. Новую категорию
зарядок Watch не создаём. Сохраняются количественная методика за период, отсутствие требования
одного чека, исходные денежные суммы и эффективный зарплатный результат. Реализация ещё впереди.

На этом шаге не меняются код расчётов, назначения, продажи, БД, зарплатные правила или
опубликованные снимки. Развитие импорта и отдельного нового интерфейса управления каталогом
приостановлено. Детализация сервиса отложена владельцем до уточнения у заказчика.

## 1. Общие правила денежных показателей

Для каждой включённой строки одна конечная денежная категория. Для продажи знак +1,
для возврата −1: количество Q = сумма знаковых количеств, выручка R = сумма знаковых
net_amount, себестоимость C = сумма знаковых cost_amount, валовая прибыль GP = R − C.
Маржа = GP / R × 100%; средняя цена категории = R / Q при допустимом знаменателе.
Суммируются исходные суммы, а не округлённые проценты/средние отдельных товаров.

Сохраняется [финансовый контракт](../current/product/business-metrics.md): одинаковые магазин,
включительный период business_date и фильтры удаления; отсутствие себестоимости хотя бы
одной включённой строки делает C/GP/маржу недоступными, а не нулевыми. Q/R доступны отдельно.
Переименование/разделение включённых категорий не меняет денежный факт. Перенос в EXCLUDE
меняет аналитический охват и требует отдельного объяснения при сверке, а не равенства сырых итогов.

Родитель — представление суммы детей, а не второе назначение строки. Телефоны входят в технику;
их нельзя ещё раз прибавлять к технике. Для текущей модели Допы = Аксессуары + Услуги,
где услуги включают SERVICE/WARRANTY/PROTECTION. Предлагаемые детальные разделы сохраняют
эти инварианты. Неразобранный остаток старой категории показывается явно, не теряется в дереве.

Полная сумма финансовых показателей сотрудников, включая «Не назначен» и сотрудников вне
рейтинга, равна магазину. Состав рейтинга не обязан равняться всем сотрудникам. STORE и SELLERS
не смешиваются в одном отношении. Возврат денег относится к исходному продавцу, до установления
исходной продажи — в «Не назначен»; это не правило авторства возврата для всех attach-метрик.

## 2. Матрица конечных категорий

Все строки, кроме EXCLUDE, участвуют в Q/R/C/GP в своём разрезе с указанными выше ограничениями.
«Аксессуары» означают также дополнительную выручку; «Услуги» также входят в Допы.
Денежные разделы ниже — целевой расчётный контракт; конкретные новые родительские коды
не вводятся этим документом. «Нет attach» означает отсутствие согласованного отдельного
числителя/знаменателя, а не отсутствие денежных показателей.

Для **каждой** строки действует зарплатное ограничение P0 из раздела 6; новый уровень здесь
не назначается. Даты, сотрудники, возвраты и версии attach определяются разделами 3–4,
а не только кодом категории. Имена N/B в таблице ссылаются на метрики раздела 3.

| `ACCESSORY_IPAD_MAC` | Сохранить старый отбор аксессуаров iPad и предупреждение неустановленной цели; не включать все Mac-аксессуары в iPad N |
| `ACCESSORY_PODS_WATCH` | Старый денежный код остаётся читаемым; одноимённый общий metric code сохраняется. Неизвестный подтип нельзя произвольно распределить между двумя новыми N |
| `FILM_PHONE` | Исторический телефонный N сохраняется; переход в нейтральную категорию только по точному решению/preview, не массовое переименование |
| `UNMAPPED` | Включён в общий денежный итог, вне именованных групп; отдельно показывать нераспределённую сумму и задачу классификации, не исключать как тест |

## 3. Матрица attach-rate

Для одного периода, магазина/cohort и версии методики: N — знаковое количество подходящих
допов, B — знаковое количество подходящих устройств. Если B > 0, процент = max(0, N) / B × 100;
иначе null. Исходные N/B не обнуляются; процент может превышать 100%. Количество хранит
точность до 0,001, результат процента — два знака HALF_UP по текущему сервису.

**Текущая общая методика количественная, а не доля чеков с комплектом.** AttachRateRepository
суммирует N и B по периоду независимо; требование «обязательно один чек с телефоном» не
добавляется ко всем товарам. Связь с устройством нужна там, где это отдельно предписано:
обычные гарантии, подтверждения совместимости неопределённых аксессуаров.

| Metric code | N | B | Статус |
|---|---|---|---|
| `CASE_APPLE_IPHONE` | Чехлы iPhone + действующие подтверждения OTHER_CASE; целевое расширение — подтверждённые продажи CASE_UNIVERSAL для iPhone | Все подходящие iPhone | Текущий состав действует; расширение CASE_UNIVERSAL согласовано, ещё не реализовано. Стёкла сюда не входят |
| `CHARGER_CABLE` | Зарядки/кабели и допустимый зарядный fallback; целевое изменение — исключить подтверждённые Watch-only зарядки | Все подходящие телефоны | Общая метрика для iPhone/Samsung сохраняется; исключение D5 согласовано, ещё не реализовано. POWER_BANK повторно не включается |
| `POWER_BANK` | Пауэрбанки | Все подходящие телефоны | Действующий отдельный показатель |
| `GLASS_IPHONE` | Защита дисплея iPhone | Все подходящие iPhone | Действует; расширение подтверждениями неизвестных стёкол предстоит |
| `GLASS_CAMERA_IPHONE` | Защита камеры iPhone | Все подходящие iPhone | Действует |
| `FILM_PHONE` | Телефонные плёнки по текущей проекции; целевое расширение — PROTECTIVE_FILM с подтверждённым телефонным назначением | Все подходящие телефоны | Расширение согласовано 2026-09-30, ещё не реализовано; неизвестные/планшетные плёнки не включать, базу не менять |
| `SETUP_SERVICE` | Подходящие услуги настройки | Телефоны + MacBook + PlayStation | Сохранять отбор конкретной версии; сервисный split отложен |
| `CASE_SAMSUNG` | Чехлы Samsung + действующие подтверждения OTHER_CASE; целевое расширение — подтверждённые продажи CASE_UNIVERSAL для Samsung | Подходящие Samsung NEW/USED | Текущий состав действует; расширение CASE_UNIVERSAL согласовано, ещё не реализовано |
| `GLASS_SAMSUNG` | Защита дисплея Samsung | Подходящие Samsung NEW/USED | Действует; неизвестные стёкла требуют нового механизма |
| `GLASS_CAMERA_SAMSUNG` | Защита камеры Samsung | Подходящие Samsung NEW/USED | Действует |
| `ACCESSORY_PODS_WATCH` | Целевая сводка N аксессуаров AirPods + N аксессуаров Apple Watch, включая согласованную Watch-only зарядную роль | AirPods + Apple Watch | Общий показатель сохраняется; новые состав/роль ещё не реализованы. Суммировать вклад детей один раз; legacy v3 EarPods описаны ниже |
| `ACCESSORY_IPAD` | Аксессуары iPad | iPad | Действует; другие планшеты не входят автоматически |
| `WARRANTY_GENERIC_USED` | Распределённые обычные гарантии Б/У | Б/У iPhone + Samsung | В v4 — атрибуция устройства |
| `WARRANTY_GENERIC_NEW` | Распределённые обычные гарантии новых | NEW/ASIS iPhone + NEW Samsung | В v4 — атрибуция устройства |

| `ACCESSORY_APPLE_WATCH` | Аксессуары Apple Watch + подтверждённые зарядки исключительно для Apple Watch из CHARGER_CABLE | Apple Watch | Новый отдельный показатель и исключение D5 приняты владельцем; ещё не реализованы. Денежная категория зарядки не меняется |

Для новой сводки: N общий = N AirPods + N Watch; B общий = B AirPods + B Watch;
затем общая формула процента. Не усреднять проценты детей, не отбрасывать ребёнка с B ≤ 0
перед суммированием исходных количеств. Детям разрешено быть недоступными по отдельности.
Не прибавлять родителя и детей как три независимых вклада в рейтинг.

Если старая денежная категория имеет неизвестный подтип, нельзя выдумывать дочернее
распределение ради равенства. Требуются проверка/явно видимый legacy-остаток; точная сводка
двух детей выпускается только с определённым охватом и проверенной совместимостью истории.
Это ограничение реализации, а не разрешение потерять прежние количества.

## 4. Версии, даты, авторство, совместимость и комплекты

- В коде есть v3 и v4. Активную production-методику здесь не утверждаем. EarPods в v3
  исторически входят в базу AIRPODS, в v4 — только HEADPHONES для Care. Новая согласованная
  пара метрик не включает EarPods; старую историю не переписывать незаметно, переход версионировать.
- В v4 обычная гарантия относится к продавцу/периоду устройства. Её возврат наследует
  распределение; возврат устройства уменьшает гарантийную базу исходного периода. Смешанный
  частичный возврат и отсутствие исходной связи требуют проверки, не предположения.
- Для остальных v4-метрик, включая Care, возврат учитывается датой возврата и по отдельному
  исходному автору LiveSklad. Неизвестный автор не заменяется финансовым продавцом: магазин
  учитывает факт, сравнение затронутого employee-показателя ограничено качеством данных.
- Название категории WARRANTY/PREMIUM не заменяет роль продукта: Care и обычная гарантия
  взаимоисключаются в N. Денежная категория Care может отличаться от кода attach-метрики.
- Проверка OTHER_CASE относится к строке продажи, не меняет постоянную совместимость SKU.
  Соседний телефон даёт предположение, не доказательство. GLASS_PHONE_UNRESOLVED должен получить
  такой же контролируемый путь подтверждения, возврата, устаревания решения и пересчёта.
  Известный другой бренд GLASS_OTHER не превращается в iPhone лишь из-за соседства в чеке.
- Для CASE_UNIVERSAL используется подтверждение целевого телефона конкретной строки продажи.
  Это атрибуция проданного чехла, не исправление его универсальной совместимости. Выбор другого
  телефона оставляет деньги в категории, но не увеличивает iPhone/Samsung attach. До решения
  нет официального вклада; предположение по чеку не подтверждает его автоматически. Связанные
  возвраты, новая ревизия и устаревание должны обрабатываться общим механизмом проверки;
  повторное сохранение не создаёт второй вклад. Базы существующих метрик не расширяются.
- Для PROTECTIVE_FILM подтверждённое телефонное назначение может быть установлено для товара
  либо решением по конкретной продаже; подтверждение продажи действует только на эту строку.
  При неизвестном назначении продажа направляется на проверку и до подтверждения не даёт
  официальный N FILM_PHONE. Подтверждённый планшет/другое не-телефонное устройство не даёт
  телефонного вклада; денежные показатели сохраняются. Совпадение товарного подтверждения
  и решения продажи не удваивает количество. Возвраты, устаревание, ревизии и пересчёт идут
  через общий механизм проверки. Явные iPad-плёнки из ACCESSORY_IPAD автоматически не переносить;
  исторический FILM_PHONE не переименовывать целиком, знаменатель телефонной метрики не расширять.
- Для зарядок правило D5 применяется по подтверждённому назначению товара исключительно для
  Apple Watch. Денежный leaf остаётся CHARGER_CABLE, числитель — ACCESSORY_APPLE_WATCH;
  телефонный N для той же строки исключён. Общая сводка получает вклад через дочерний N Watch,
  а не вторым независимым добавлением. Прямая категория и роль не могут дважды учесть количество.
  Подтверждение назначения переиспользуется автоматически, пока оно действительно; новые
  существенные сведения/конфликт отправляются на проверку. Часы в том же чеке не обязательны.
  Возврат вычитает соответствующий вклад по принятой методике возвратов; историю и снимки
  не переписывать только потому, что сегодня появилось новое подтверждение. Многофункциональные
  станции не попадают в Watch-only по простому упоминанию Watch или по совместимости с Watch
  наряду с телефоном/AirPods. Их новое распределение требует отдельного решения.
- Значимое изменение исходных данных делает решение устаревшим; новое решение — новая ревизия
  с автором/причиной. Изменение одной цены не меняет совместимость. Повтор синхронизации без
  значимого изменения не создаёт повторного вклада. Межмагазинные связи не разрешаются;
  перенос продаж между магазинами не является рабочим сценарием владельца.
- Подтверждённый комплект VLP NEO — одна единица зарядного комплекта без второго POWER_BANK N.
  Аналогично нельзя создавать из одной строки «чехол + стекло» два вклада без отдельного
  согласованного правила состава. Зарядный брелок Watch остаётся в денежной CHARGER_CABLE;
  при подтверждённом исключительном назначении его роль в attach — аксессуар Watch по D5.
  Это не перенос денежной категории и не второй вклад в телефонные зарядки.
- Неизвестная совместимость не равна «другой бренд», универсальность не равна неизвестности,
  а общая планшетная плёнка не подтверждает телефон. Эти состояния должны быть видны руководителю.

окончательную сверку после реализации он не заменяет.

## 6. Зарплатный gate P0 и критерии проверки

P0: сохранить эффективную зарплатную классификацию и результат для каждого затронутого
факта/даты. В PayrollSalesRepository сначала действует датированный ручной override, затем
resolve_default_payroll_category и default категории. Для возвратов важна дата исходной продажи.
Нельзя заменить это одним новым default для всей объединённой категории или массовыми
бессрочными ручными override, мешающими будущей реформе. Если delta ненулевая, пакет останавливается
до совместимого решения. Уровни, ставки, утверждённые/выплаченные расчёты не пересматриваем.

Локальная приёмка этапа 4 включает:

1. Полное покрытие кодов итогового каталога, legacy-кодов и согласованных категорий без строк.
2. Равенство Q/R/C/GP до/после на неизменном охвате; объяснимые переносы между ветками.
   При null себестоимости сохраняются null и причина, а не ложное равенство прибыли нулю.
3. Суммы непересекающихся листьев равны родителю с явным нераспределённым остатком;
   финансовая сумма всех сотрудников равна магазину. Не усреднять проценты.
4. Для каждого attach — fixtures продажи, возврата в другом периоде, неизвестного автора,
   нулевой/отрицательной базы, N < 0, N > B, дробного количества и legacy-методики.
5. AirPods/EarPods/Watch, часы Samsung вместо телефона, игровая периферия вместо консоли,
   зарядный комплект, известная/неизвестная/универсальная совместимость — отдельные regression cases.
   Для D5 отдельно: подтверждённая Watch-only зарядка, её связанный возврат, неизвестное назначение,
   многофункциональная станция, независимая продажа без часов в чеке, автоматическое повторное
   применение подтверждения без второго N, равенство сводки сумме исходных дочерних N/B.
6. Сохранение, повтор сохранения, конфликт ревизий, устаревание и возврат решения проверки
   не удваивают вклад. Перечитываются все затронутые live-показатели; ошибка не показывается как успех.
7. Текущий Weekly Review корректно переоценивается; опубликованные снимки не меняются молча.
   Рейтинг не получает новых весов автоматически из количества категорий/дочерних виджетов.
8. P0, неизменность отложенного сервисного блока и локальная визуальная проверка при изменении UI.
9. На этапе 5 — сверка LiveSklad ↔ нормализованные факты ↔ категории/показатели по каждому магазину,
   периоду, документу/строке, возврату и сотруднику. Только равенства общей выручки недостаточно.
   Совпадение требуется в согласованном охвате: EXCLUDE/удаления/скидки/даты/качество источника
   перечисляются отдельно. Наш attach-rate сверяется с нашей методикой, не с названием отчёта LiveSklad.
