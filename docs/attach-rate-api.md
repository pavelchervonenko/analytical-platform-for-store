# Attach-rate API

Статус: `attach-rate-v3` — актуальная согласованная методика заказчика от 2026-08-17.
Расчёт выполняется по нормализованным данным PostgreSQL, без обращения к LiveSklad или LLM.

## Главное правило

Attach-rate считается по чистому количеству проданных единиц, а не по чекам и не по связи
«устройство и доп в одном документе»:

```text
attach-rate = max(0, продажи допа - возвраты допа)
              / (продажи релевантной техники - возвраты техники) * 100%
```

- каждая единица товара или услуги учитывается отдельно;
- один чек может дать несколько единиц в числитель и знаменатель;
- числитель и знаменатель считаются независимо, совместный чек не требуется;
- возврат допа уменьшает числитель, возврат техники уменьшает соответствующую базу;
- возврат относится к продавцу исходной продажи: это зафиксировано при нормализации возврата;
- отрицательный чистый числитель сохраняется в контрольной расшифровке, но процент показывается
  как `0%`;
- при нулевом или отрицательном знаменателе процент равен `null`;
- исходные количества не округляются; API выдаёт количество с точностью до 3 знаков и процент
  с точностью до 2 знаков, интерфейс показывает процент с 1 знаком.

## Endpoint

```text
GET /api/stores/{storeId}/kpi/attach-rates?periodStart=2026-07-01&periodEnd=2026-07-31
```

Даты обязательны и включаются в период. Нужны действующая сессия, завершённая обязательная смена
пароля и доступ к магазину.

Пример:

```json
{
  "storeId": "00000000-0000-0000-0000-000000000000",
  "periodStart": "2026-07-01",
  "periodEnd": "2026-07-31",
  "formulaVersion": "attach-rate-v3",
  "dataQuality": {
    "unmatchedNumeratorItemCount": 0,
    "ambiguousWarrantyItemCount": 0,
    "unknownDeviceConditionItemCount": 0
  },
  "rates": [
    {
      "metricCode": "CASE_APPLE_IPHONE",
      "numeratorCategoryCode": "CASE_APPLE_IPHONE",
      "denominatorCode": "IPHONE",
      "numeratorQuantity": 25.000,
      "denominatorQuantity": 20.000,
      "ratePerHundred": 125.00
    }
  ]
}
```

`numeratorQuantity` и `denominatorQuantity` — актуальные поля. Устаревшие JSON-поля
`numeratorReceiptCount` и `denominatorReceiptCount` пока возвращаются с теми же количествами для
совместимости старых сохранённых отчётов; это больше не количество чеков.

`denominatorCode` сохраняет совместимые enum-значения v2; точная база определяется
`metricCode` по таблице ниже. Поле не используется при вычислении v3.

## 14 показателей

Порядок строк стабилен и совпадает с методикой заказчика:

| № | Metric code | Чистый числитель | Чистый знаменатель |
|---:|---|---|---|
| 1 | `CASE_APPLE_IPHONE` | чехлы именно для iPhone | новые iPhone + ASIS/ASIS+ iPhone + Б/У iPhone |
| 2 | `CHARGER_CABLE` | СЗУ, АЗУ, БЗУ, блоки питания, зарядки, кабели, провода, переходники и адаптеры для зарядки/подключения | все телефоны |
| 3 | `GLASS_IPHONE` | только экранные защитные стёкла iPhone | все iPhone |
| 4 | `GLASS_CAMERA_IPHONE` | защита камеры/линз iPhone | все iPhone |
| 5 | `FILM_PHONE` | защитные плёнки смартфонов | все телефоны |
| 6 | `SETUP_SERVICE` | все услуги настройки, включая установку защитного покрытия | телефоны + MacBook + PlayStation |
| 7 | `CASE_SAMSUNG` | чехлы именно для Samsung | новые + Б/У Samsung |
| 8 | `GLASS_SAMSUNG` | только экранные защитные стёкла Samsung | новые + Б/У Samsung |
| 9 | `GLASS_CAMERA_SAMSUNG` | защита камеры/линз Samsung | новые + Б/У Samsung |
| 10 | `ACCESSORY_PODS_WATCH` | аксессуары именно для AirPods/Apple Watch | AirPods + Apple Watch |
| 11 | `ACCESSORY_IPAD` | аксессуары именно для iPad | только iPad; MacBook/iMac не входят |
| 12 | `WARRANTY_GENERIC_USED` | гарантии для Б/У телефонов | Б/У iPhone + Б/У Samsung |
| 13 | `WARRANTY_GENERIC_NEW` | гарантии для новых телефонов | новые iPhone + ASIS/ASIS+ iPhone + новые Samsung |
| 14 | `PREMIUM_PROTECTION` | только `PRIVILEGE CARE`, `ULTIMATE CARE+`, `ELITE CARE` | новые/ASIS/Б/У iPhone, новые/Б/У Samsung, Mac/MacBook, iPad, Apple Watch, AirPods/наушники, PlayStation |

Dyson в базу `PREMIUM_PROTECTION` не входит. Установка защитного покрытия относится к
`SETUP_SERVICE`, а не к протекции. Экранное стекло и защита камеры всегда являются разными
метриками и для iPhone, и для Samsung.

## ASIS и гарантии

ASIS/ASIS+ применяется только к новым iPhone. Он входит в базы всех iPhone, всех телефонов,
новых телефонов, настроек и протекции; к Samsung, Mac, iPad, Watch и другой технике ASIS не
применяется.

В текущем каталоге нет отдельного структурированного признака назначения гарантии. Поэтому
реализация использует одно централизованное семантическое правило, которое можно заменить без
возврата к расчёту по чекам:

- `Check Discount*` / `Check Diskount*` — гарантия Б/У телефона;
- остальные `Check*`, включая `Check+`, `Check++` и `Check Premium`, — гарантия нового телефона;
- `Privilege Care`, `Ultimate Care+`, `Elite Care` — только
  `PREMIUM_PROTECTION`, не гарантия;
- неизвестная гарантийная позиция не угадывается и увеличивает
  `ambiguousWarrantyItemCount`.

Это правило должно быть отдельно подтверждено заказчиком, если у него есть иной список
номенклатуры гарантий для новых и Б/У телефонов.

## Контроль качества

- `unmatchedNumeratorItemCount` — аксессуары старой объединённой категории iPad/Mac, которые
  нельзя уверенно отнести именно к iPad;
- `ambiguousWarrantyItemCount` — гарантийные/защитные позиции, не распознанные как один из
  согласованных `Check*` или трёх Care-продуктов;
- `unknownDeviceConditionItemCount` — iPhone/Samsung с состоянием вне `NEW`, `ASIS`, `USED`.

Удалённые документы, удалённые строки и категория `EXCLUDE` не участвуют. Расчёт магазина и
каждого сотрудника использует одну и ту же item-level проекцию `attach_rate_item_facts_v3`.

## Проверки реализации

Интеграционные тесты обязаны подтверждать:

- все 14 строк и их точный порядок;
- количество единиц, включая несколько единиц в одном чеке и доп без устройства в том же чеке;
- вычитание возврата из нужного числителя/знаменателя;
- сохранение отрицательного чистого числителя и показ `0%`;
- отдельные базы iPhone/Samsung, экран/камера, iPad, Pods/Watch, настройки, гарантии и протекция;
- включение ASIS только в новый iPhone;
- исключение Dyson и лишних сервисов из протекции;
- изоляцию другого магазина и одинаковую методику для сотрудника и магазина.

## Ошибки endpoint

- `400 INVALID_ARGUMENT` — период некорректен;
- `401 AUTHENTICATION_REQUIRED` — нет действующей сессии;
- `403 ACCESS_DENIED` — нет доступа к магазину или не завершена смена пароля;
- `404 STORE_NOT_FOUND` — магазин не существует.
