# Frontend handoff Store Analytics

Дата сверки с кодом: 2026-08-24.

Документ описывает действующий SPA-контракт. Конкретные действия и invalidation:
[frontend-actions.md](frontend-actions.md). Transport source of truth:
`contracts/openapi/current.json` и generated types в `frontend/src/api/generated/`.

## 1. Состояние

- React 19, TypeScript 6, Vite 8, React Router, TanStack Query и Zod;
- production сейчас соответствует `v0.1.0-pilot.22`;
- текущий неразвернутый кандидат меняет `/overview`, `/plan` и `/insights`;
- полный кандидатный frontend check: `38` файлов / `143` теста, ESLint, contract check, build;
- затронутые страницы проверены локально на desktop/tablet/mobile.

Frontend не обращается к LiveSklad и не вычисляет бизнес-итоги из raw данных.

## 2. Маршруты

| Маршрут | Назначение |
| --- | --- |
| `/login` | вход |
| `/overview` | KPI, структура продаж, категории, карта допродаж |
| `/employees` | рейтинг и список сотрудников |
| `/employees/:employeeId` | карточка сотрудника |
| `/insights` | недельный ИИ-разбор |
| `/plan` | месячный план, дневные цели и смены |
| `/payroll` | readiness, расчет, ревизии, утверждение и выплата |
| `/reports` | immutable месячные/годовые отчеты |
| `/quality` | качество данных и рекомендуемые действия |
| `/profile` | профиль, sessions и Telegram |
| `/admin` | пользователи, sync, классификация, схемы, ИИ/Telegram |

`/admin` и навигационный раздел «Система» доступны только ADMIN. Router guard улучшает UX, но
backend authorization всегда является окончательной границей.

## 3. Периоды

- `/overview`, `/employees` и карточка принимают неделю, месяц или произвольный включительный
  диапазон;
- `/plan`, `/payroll` и месячная quality-логика используют отдельный календарный месяц;
- query key включает каждый `storeId`, период, месяц и resource ID;
- «Август» и «1–19 августа» — разные запросы: полный месяц может включать факты/coverage после 19-го
  либо отличаться режимом текущего незавершенного месяца;
- frontend не обрезает произвольный период и не пересчитывает comparison.

## 4. Текущие правила представления

### Структура продаж

Блок иерархический:

- «Техника» — родительская сумма;
- «Телефоны» — вложенная часть техники;
- «Дополнительная выручка» — родитель;
- «Аксессуары» и «Услуги» — ее составляющие.

Родительские и дочерние строки нельзя визуально складывать как независимые итоги.

### Карта допродаж

- магазинный benchmark включает все документы магазина, в том числе продажи вне рейтинга и без
  сотрудника;
- сотрудники основной матрицы берутся из активного roster рейтинга;
- остаток между итогом магазина и показанными участниками выводится отдельной колонкой
  «Вне рейтинга»;
- цвет сотрудника показывает относительное положение к магазинному benchmark;
- числитель, знаменатель, unit и `included` приходят с backend.

### План и смены

Различаются:

- полный месячный план;
- выполнение полного плана;
- темп выполнения на дату среза;
- остаток полного плана;
- необходимый темп/сумма в день до конца месяца;
- целевое значение конкретного будущего дня.

«Нужно в день» пересчитывается, потому что меняются факт, дата среза, остаток и количество будущих
дней. Для долевых направлений UI не выдает денежный ориентир за сам criterion.

### ИИ-разбор

- evidence отображается непосредственно рядом с выводом;
- общий дублирующий блок «Данные» не создается;
- `LIMITED`/недоступные данные получают честное объяснение;
- технические refs, псевдонимы и raw snapshot поля не показываются пользователю;
- шаблонный текст не заменяет отсутствующий вывод.

## 5. Auth, errors и mutations

- cookie session; bearer token в браузере не хранится;
- CSRF token живет только в памяти и отправляется mutation-клиентом;
- при `passwordChangeRequired` разрешен только password/session lifecycle;
- `401` очищает session state; `403` не маскируется как пустые данные;
- `409` для optimistic version требует refetch и повторного решения пользователя;
- correlation ID и серверные детали остаются в transport/операторской диагностике;
- mutation инвалидирует authoritative queries и не вносит оптимистически рассчитанные бизнес-итоги.

## 6. Data quality

`null`, unknown и incomplete нельзя отображать как ноль. Blocking issue и warning сохраняют
severity backend. UI показывает действие только при поддержанном `recommendedAction`; нельзя
создавать кнопку, которая не обеспечена API.

Незаклассифицированный товар остается blocking для зависимых зарплатных расчетов, пока
классификация не подтверждена и не перечитана соответствующая проекция.

## 7. Локальная проверка

```bash
cd frontend
npm ci
npm run check
VISUAL_ROUTES='/overview,/plan,/insights' npm run visual:local
```

Visual command разрешен только для loopback frontend/backend. После успешной команды обязательно
вручную посмотреть изображения в `frontend/visual-artifacts/`. Их нельзя коммитить: на них могут
быть бизнес-данные.

Credentialed E2E получает учетные данные только из environment/CI secrets. Мутационный lifecycle
MANAGER запускается только против локальной или специально подготовленной staging БД.
