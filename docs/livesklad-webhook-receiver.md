# LiveSklad return webhook receiver

## Scope

This release adds two authenticated ingress endpoints:

- `POST /api/integrations/livesklad/webhooks/sale-returns`
- `POST /api/integrations/livesklad/webhooks/order-returns`

The receiver durably stores and deduplicates notifications. It does not yet
fetch the full sale/order or update analytical facts. That processing is a
separate release after real payloads have been captured and verified.

## Public URLs

- `https://store-analytics.net/api/integrations/livesklad/webhooks/sale-returns`
- `https://store-analytics.net/api/integrations/livesklad/webhooks/order-returns`

Use separate LiveSklad webhooks and separate secrets for the two events.

## LiveSklad configuration

Sale return webhook:

- name: `Store Analytics - sale returns`
- event: sale return
- URL: the sale-return URL above

Order return webhook:

- name: `Store Analytics - order returns`
- event: order return
- URL: the order-return URL above

Add these custom headers to each webhook:

- `X-Store-Analytics-Webhook-Token`: the endpoint-specific secret
- `X-LiveSklad-Verification`: the verification value generated by LiveSklad

Never reuse the sale secret for the order endpoint. Never place either secret
in source control, a ticket, chat, command history, or application logs.

Select only the minimum event fields needed for reconciliation. In particular,
do not select customer identity, passport, bank, address, phone, email, IP, or
other unrelated personal data.

## Protocol

The receiver:

- accepts HTTPS JSON `POST` requests only;
- requires the endpoint-specific authentication header;
- limits the body to the configured byte size;
- echoes the LiveSklad verification value during URL verification;
- responds with HTTP 200 and the exact text `OK` only after an event is
  persisted;
- keeps the first payload and counts retries by `eventId`;
- flags a retry whose payload differs from the first delivery;
- returns a non-2xx response if authentication, validation, or persistence
  fails so LiveSklad can retry.

## Production configuration

Environment:

- `LIVESKLAD_WEBHOOK_ENABLED=true`
- `LIVESKLAD_WEBHOOK_MAX_BODY_BYTES=262144`
- `LIVESKLAD_SALE_RETURN_WEBHOOK_SECRET_FILE`
- `LIVESKLAD_ORDER_RETURN_WEBHOOK_SECRET_FILE`

Secret files must be root-owned, mode `0600`, and contain URL-safe random
values of 32 to 256 characters.

## Storage

Migration `V39.1__add_livesklad_webhook_inbox.sql` creates
`livesklad_webhook_receipts`. The unique key is
`(webhook_kind, event_id)`, matching LiveSklad's stable `eventId` retry
contract.

The payload column is internal and must not be exposed through the application
API. Access should be limited to operational diagnostics and the future
