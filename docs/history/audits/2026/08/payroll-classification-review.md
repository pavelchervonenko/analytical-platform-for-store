# Payroll classification review

Дата проверки: 2026-07-27.

Статус: review воспроизводим, все 44 подтвержденных назначения применены к persistent dev-БД.

## Назначение

Перед тестовой отдачей неоднозначные товары должны получить effective-dated payroll override.
Сам review остается воспроизводимым отчетом и самостоятельно БД не изменяет. При применении его
внешние идентификаторы LiveSklad были сопоставлены с внутренними UUID товаров одной integration
connection, после чего назначения записаны одной транзакцией.

Воспроизводимый отчет строится из уже утвержденной аналитической классификации:

```bash
scripts/generate-payroll-classification-review.sh \
  outputs/category-review-approved/product-category-assignments-v2.json \
  outputs/payroll-classification-review-v1.json
```

Второй аргумент обязателен для безопасного сохранения: скрипт атомарно публикует только новый файл
с mode `0600`, владельцем становится запустивший его оператор, а существующий файл никогда не
перезаписывается. Вывод в stdout оставлен только для временного pipeline; shell redirect не
гарантирует нужный mode, потому что файл открывает родительский shell до запуска скрипта.

`outputs/` исключен из Git как customer-derived confidential storage. Артефакт нужно удалить
сразу после завершения review/import; максимальный локальный срок хранения — 30 дней, если для
конкретного расследования или юридического hold письменно не зафиксирован другой срок. Копирование
в общие каталоги, task attachments и неуправляемые cloud-диски запрещено.

## Подтвержденные правила

- MacBook — `TECH_TIER_1`;
- iPad — `TECH_TIER_2`;
- самостоятельная техника Dyson — `TECH_TIER_1`;
- консоль PlayStation 5 — `TECH_TIER_1`.

Фильтр сначала учитывает аналитическую категорию, поэтому чехлы, пленки, настройка MacBook,
аксессуары iPad, док-станция и контроллеры DualSense не получают категорию техники по одному
совпадению в названии.

Начиная со схемы V34 эти подтвержденные однозначные правила являются также runtime-default:
MacBook, iPad, Dyson и PlayStation 5 классифицируются для зарплаты при появлении нового товара,
если его аналитическая категория уже подтверждена. Явное effective-dated назначение остается
приоритетным. Поэтому артефакт review нужен для воспроизводимости и аудита первоначальной выборки,
но ежедневная синхронизация больше не должна создавать ручную работу только из-за нового UUID
той же однозначной модели. Неоднозначные товары, подписки и платный ремонт по-прежнему требуют
явного подтверждения.

Текущий approved-каталог дает 44 однозначных кандидата:

| Правило | Payroll category | Товаров |
| --- | --- | ---: |
| MacBook | `TECH_TIER_1` | 25 |
| iPad | `TECH_TIER_2` | 15 |
| Dyson | `TECH_TIER_1` | 3 |
| Консоль PlayStation 5 | `TECH_TIER_1` | 1 |

В каталоге не найдены отдельные позиции подписок PlayStation и платного ремонта. Их нельзя
угадывать по товарам со словом «ремонт» внутри названия устройства: соответствующие payroll
категории назначаются только отдельным продаваемым услугам после появления таких позиций.

## Результат применения

- persistent dev-БД обновлена с Flyway V3 до V9 штатными миграциями приложения;
- все 44 внешних идентификатора однозначно сопоставлены товарам `livesklad-default`;
- атомарно назначены 29 `TECH_TIER_1` и 15 `TECH_TIER_2`;
- у всех назначений `validFrom=2026-01-01`, поэтому история до этой даты не переписывается;
- временная роль миграции удалена, владение объектами возвращено основной роли БД;
- `.env` не читался и не загружался.

В persistent dev-БД пока нет магазинов, продаж и возвратов. После первой синхронизации контрольного
месяца нужно вызвать payroll readiness каждого магазина и вручную классифицировать оставшиеся
проданные позиции `UNMAPPED`; автоматическое назначение неподтвержденных категорий запрещено.
