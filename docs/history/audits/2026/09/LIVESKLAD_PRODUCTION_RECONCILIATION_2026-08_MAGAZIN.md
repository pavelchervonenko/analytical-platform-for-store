# Сверка LiveSklad ↔ production: август 2026, МАГАЗИН

## Вердикт

`PASS_WITH_LIMITS`. В области `STORE` чистая выручка, себестоимость, валовая прибыль,
маржа, документы, товарные единицы, продажи, возвраты продаж, позиции выданных заказов,
структура, 20 аналитических и четыре зарплатные категории совпали. Денежное движение
также совпало с колонками оплаты отчёта LiveSklad.

Ненулевые различия в `SELLERS` полностью формируют два возврата: приложение в соответствии
с ADR-0001 относит их к сотруднику исходной продажи, а XLSX показывает сотрудника в самом
документе возврата. Это ожидаемая разница семантики, а не потеря или двойной учёт выручки.

Ограничения доверия:

- четыре позиции имеют `ZERO_UNEXPECTED`; нулевая себестоимость пришла из LiveSklad и одинаково
  учтена обеими сторонами, но экономическая валовая прибыль может быть завышена на ещё не
  установленную фактическую себестоимость этих позиций;
- XLSX не содержит аналитических и зарплатных категорий, поэтому таблицы категорий доказывают
  правильность агрегации по действующим назначениям production, но не являются повторным
  бизнес-согласованием каждого назначения;
- «выданные заказы» в XLSX включают шесть нулевых/пустых заказов, тогда как приложение хранит
  sales facts только для пяти заказов с позициями;
- время в XLSX показано как UTC+3, хотя требуемая бизнес-зона магазина и production —
  `Europe/Kaliningrad` (UTC+2 в августе). На границы августовского периода это не повлияло.

Никакие backfill/resync, изменения БД, категорий, кода или production не выполнялись.

Сами XLSX не сохраняют экранные настройки фильтра как метаданные. Поэтому выше разделены
подтверждённые пользователем параметры и effective filter, доказуемый содержимым: например,
в отчёте заказов есть созданный 22 июня заказ, выданный 16 августа, что подтверждает отбор по
дате выдачи. Другие незафиксированные UI-переключатели нельзя задним числом объявлять проверенными.

Семантика сверялась не по названию отчёта, а по колонкам и строкам. В отчёте «Товары и работы»
`Себестоимость = Сумма - Валовая прибыль (руб)`. Продажа имеет положительный знак, sale return —
отрицательный; позиции заказа входят по дате добавления позиции, а не по дате выдачи заказа.
Официальные описания: [товары и работы](https://help.livesklad.com/ru/articles/292-%D0%BF%D0%BE%D0%B4%D1%80%D0%BE%D0%B1%D0%BD%D1%8B%D0%B9-%D0%BE%D1%82%D1%87%D1%91%D1%82-%D0%BF%D0%BE-%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%B0%D0%BC-%D0%B8-%D1%82%D0%BE%D0%B2%D0%B0%D1%80%D0%B0%D0%BC),

## Полнота синхронизации

За август найдены 38 пересекающих период sync jobs. В истории есть промежуточные failed/cancelled
runs, но их интервалы перекрыты последующими успешными backfill/incremental runs. Начало месяца
покрыто успешным backfill `2026-06-30T22:00Z..2026-08-06T22:00Z`, середина — успешным backfill
`2026-07-31T22:00Z..2026-08-19T22:00Z`, конец — последовательными трёхдневными incremental
окнами до `2026-09-02T22:00Z`.

Главное доказательство полноты — не статус job, а текущая предметная сверка:

- 1,350 из 1,350 документов найдены с обеих сторон; source-only = 0, app-only = 0;
- 3,365 из 3,365 групп `document + product` сопоставлены; unmatched = 0;
- для всех 1,350 документов и 3,365 групп расхождение quantity/revenue/cost/GP равно нулю;
- активных удалённых документов/строк в августовском production scope нет;
- все 61 sale return имеют исходную продажу, тот же магазин и employee attribution исходной
  продажи; orphan/misattributed returns = 0;
- `UNMAPPED = 0`, `EXCLUDE = 0`, missing cost = 0.

Возможное изменение заказа во время прежнего sync не оставило остаточного эффекта: текущие пять
order-position facts совпали с текущим XLSX по документу, позиции, quantity, amount и cost.

Следовательно, на момент снимка синхронизация поставленных отчётных данных за август полна.
Наблюдаемые старые ошибки запусков не формируют остаточную разницу.

| Отличие формул | подтверждено и объяснено | cash vs merchandise; 11 orders vs 5 position-bearing; STORE vs SELLERS |
| Отличие границ периода | financial effect 0 | API UTC probe, same business dates |
| Дубликат или удаление | financial effect 0 | six merged row pairs; no deleted August facts |
| Ошибка исходных данных LiveSklad | четыре возможных zero-cost cases | `ZERO_UNEXPECTED` rows |
| Ошибка приложения | не обнаружена | все STORE monetary/unit deltas zero; app formulas independently recomputed |

## Вывод и безопасные дальнейшие действия

1. Точно совпали все STORE financial/unit metrics, documents, product groups, cash movement,
   структуры, категории и store attach-rate.
2. Не совпадают только employee allocation двух returns, четыре seller attach cells, техническое
   количество строк и operational count пустых выданных заказов; все различия объяснены.
3. Финансовую SELLERS-разницу формирует только `F000430`; `F000395` перераспределяет значения
   внутри SELLERS. Остальные exception documents перечислены выше.
4. Первопричины: ADR-0001 return attribution, разные формулы cash/merchandise и order/item counts,
   mutable LiveSklad product names, XLSX UTC+3 presentation и четыре source zero costs.
5. Исправление production данных или формул для августа не требуется. Нужна проверка закупочной
   стоимости четырёх `ZERO_UNEXPECTED` строк в LiveSklad. Изменять её в приложении вручную нельзя.
6. Повторная синхронизация сейчас не требуется. Если source costs будут исправлены, отдельное
   согласование должно определить точечную историческую синхронизацию и повтор этой сверки.
7. Показателям августа можно доверять для STORE и для SELLERS при явном понимании original-sale
   attribution. GP/margin имеют ограничение по четырём zero-cost строкам; count выданных заказов
   означает пять заказов с sales positions, а не все 11 operational order records.

До устранения source-cost uncertainty статус остаётся `PASS_WITH_LIMITS`, но оснований для
backfill, ручной корректировки, смены категорий или кода не найдено.
