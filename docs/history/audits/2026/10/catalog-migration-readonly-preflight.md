# Проверка исходного состояния каталожных миграций

## Область и происхождение

Владелец выполнил проверенный экспорт на сервере. Через существующий SSH-канал получены
только `snapshot.jsonl` и `snapshot.sha256`. Транзакция завершена ROLLBACK; read-only guard
подтверждён в начале и конце. Время снимка: 2026-09-30 21:27:04 UTC,
то есть 2026-10-01 00:27:04 Europe/Moscow.

SHA-256 выгрузки: `ac2f43c4a3aade02d5697a98bfa9bcaa4279c3b00bbb9646e64998abc20bd2b6`.
Приватные файлы сохранены в игнорируемой папке
`outputs/catalog-audit-2026-10-01/migration-state-8ofJfCMm/`; в Git не включаются.
Фактическая schema version отражена только в [project-state](../../../../current/project-state.md).

## Подтверждено

- Экспорт содержит 55 JSON-строк: начало, 52 записи истории, признаки наличия данных, конец.
- Времена начала/конца совпадают, количество записей соответствует manifest.
- Все записи истории успешные SQL; ранги последовательны, версии уникальны.
- Checksum всех 52 применённых файлов совпадает с текущими исходниками. Локальные значения
  вычислены штатным `ChecksumCalculator` из закреплённой зависимости Flyway, а не SHA-256 SQL.
- В сравнении с текущей локальной цепочкой остаются 37 файлов. Среди них все 19 известных
  каталожных миграций с историческими записями, перечисленных в `CatalogMigrationPreflight`.
- В базе имеются позиции продаж, аналитические и зарплатные назначения. Выгружалось только
  наличие строк; конкретные товары, суммы, пользователи и provider payload не извлекались.

## Вывод и ограничения

Предохранитель исторических переклассификаций нужен для фактического исходного состояния,
а не только для синтетической тестовой базы. Обычный deploy текущей цепочки не разрешён:
нужно подготовить перспективный путь и репетировать его на восстановленной копии.

Проверка не подтверждает, что неприменённые здесь SQL никогда не публиковались в другом
окружении. Она не разрешает переписывать опубликованные миграции, пропускать их через
ручное редактирование Flyway history или выключать guard. Сопоставление относится к файлам
рабочей копии на момент проверки, не к ещё не собранному release image.

Не выполнялись migration/apply, backfill, изменения зарплат, ACL, runtime flags или release marker.
Не проверялись release digest, состояние контейнеров, полнота бизнес-данных и restore.
Сохранность прошлых показателей после изменения views, повторного sync и возвратов остаётся
отдельным обязательным gate.
