# Аудит периода «Август» и диапазона 1–19 августа

Дата проверки: 2026-08-20.

## Обнаруженная несогласованность

В режиме `MONTH` интерфейс передает в KPI полный календарный месяц:
`periodStart=2026-08-01`, `periodEnd=2026-08-31`.

При ручном выборе 1–19 августа интерфейс передает:
`periodStart=2026-08-01`, `periodEnd=2026-08-19`.

Для текущего месяца дата последнего завершенного дня (`asOfDate=2026-08-19`)
применяется к планам и качеству данных, но не ограничивает период финансовых KPI.
Backend включает документы по `business_date` между переданными границами включительно.

Следствие: любая уже сохраненная запись с датой 20–31 августа входит в режим
«Август», но не входит в ручной диапазон 1–19. Наблюдаемая разница 1 000 ₽
согласуется с наличием такой записи после 19 августа.

## Риск

Текущий месяц может показывать незавершенный день и расходиться с CRM-отчетом,
построенным по последний полностью синхронизированный день. Разные экраны также
могут использовать разные даты отсечения: полный месяц для KPI и `asOfDate` для
планов/качества.

## Рекомендация

Ввести единую эффективную дату окончания отчетного периода. Для текущего месяца
она должна быть не позднее последнего полностью синхронизированного завершенного
дня; для закрытого месяца — последний день месяца. Эту дату нужно одинаково
использовать во всех KPI, планах, карточках сотрудников и проверках качества.

Добавить регрессионный тест: при текущей дате 20 августа режим «Август» и ручной
диапазон 1–19 должны давать одинаковые финансовые KPI, если данные подтверждены
только по 19 августа.

## Требует подтверждения на production

Нужно определить конкретный документ/позицию на 1 000 ₽ с `business_date` после
19 августа. Во время проверки ранее настроенный временный SSH-agent уже не был
доступен, поэтому конкретная запись пока не идентифицирована.
